# Keep deleted built-in events from being reseeded

<objective>
Make an admin deletion of a built-in catalog event persistent across backend restarts while preserving hard-delete behavior and existing booking protection.

Purpose: Prevent `ensureEventCatalog()` from recreating a built-in Event document after it has been explicitly deleted by an admin.
Output: A separate `PlatformSetting` tombstone record, startup skip logic, an admin-delete mark only on successful built-in deletion, and focused mocked backend regression coverage.
</objective>

<execution_context>
Use the existing Node test runner and Mongoose model patterns. No real MongoDB, API, provider, or external service operations are allowed.
</execution_context>

<constraints>
- Preserve the existing dirty work in `backend/src/routes/admin.js`; inspect and integrate without replacing or reverting unrelated changes.
- Store tombstoned built-in event IDs under a separate `PlatformSetting.key` record (for example `deletedBuiltInEventIds`) using the existing `Schema.Types.Mixed` value. Keep the `platform` key unchanged for public platform settings.
- Do not change any schema, payment logic, booking protection, public event filtering, or public settings behavior.
- Mark a tombstone only when the event ID is present in the built-in catalog and the delete operation reports a successful hard-delete.
- Keep seeding and updates for all non-tombstoned built-in catalog entries unchanged.
- No staging, commits, push, deployment, or real database/API operations.
</constraints>
